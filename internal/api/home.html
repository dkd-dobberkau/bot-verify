bot-verify

Is this request really from the bot it claims to be?

A User-Agent string is free text: anyone can call themselves GPTBot or Googlebot. Most bot operators publish how to check the claim, as an IP list or a reverse-DNS domain, each in their own place and format. bot-verify collects those published methods and answers the question for an IP address and a bot.

It uses only what operators publish about their own bots. The bot catalog and the reasoning behind it come from goodbot-badbot.com/bots.

Ask

curl 'https://verify.goodbot-badbot.com/v1/verify?ip=66.249.66.1&bot=googlebot'
{"ip":"66.249.66.1","bot":"googlebot","result":"confirmed","method":"ip_list",
 "sources":["https://developers.google.com/static/crawling/ipranges/common-crawlers.json", …],
 "data_age_seconds":2364}

Ask about the address of the TCP peer, or the one set by the reverse proxy you control. Never the left-most X-Forwarded-For entry: the client writes that, and a "confirmed" for a forged IP is worse than no answer.

Answers

confirmedThe IP is in the operator's published list, or its reverse-DNS name is under the operator's domain and resolves back to the same IP.
refutedThe operator's lists are loaded and the IP is not in them, and the reverse-DNS check, if the operator offers one, gave a definite no.
not_checkableThe operator publishes nothing to check against, DNS did not answer, or the lists have not loaded yet. Never treat this as refuted.

Endpoints

GET
/v1/botsThe bots that can be asked about, with their ids
/v1/verify?ip=…&bot=…The answer for one IP address and bot id
/v1/datasetPer bot its reverse-DNS domains, its IP lists with all prefixes, or why it cannot be checked
/healthz, /readyzLiveness and readiness

Requests to /v1/ are rate-limited per client network (IPv4 /24, IPv6 /56). Over the limit the answer is 429 with Retry-After.

Privacy

bot-verify stores no visitor data and does not log the IP addresses it is asked about, nor those of its clients: its log holds method, path, status and duration per request. The hosting provider's web server in front of it may keep access logs; see Datenschutz.
